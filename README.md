# ближе

Мобильное пространство для двоих на React и TypeScript: дни вместе, памятные фотографии, даты, планы, чат, аккаунты и профили. Мягкая палитра и стеклянные поверхности вдохновлены iOS Liquid Glass.

## Запуск

Нужен Node.js 24.12+ с npm (сервер использует встроенный SQLite).

```sh
npm install
npm run dev -- --port 8000 --strictPort
```

Откройте http://localhost:8000. С телефона в той же сети откройте Network-адрес, который покажет Vite. Компьютер должен оставаться включённым. Фронтенд и API обслуживаются одним процессом, отдельный запуск базы не нужен.

```sh
npm run build
npm run preview -- --port 8000 --strictPort
```

Перед запуском preview остановите dev на том же порту. Папка dist содержит фронтенд; для работы аккаунтов также нужны сервер из server/api.mjs и SQLite. Простая публикация dist на статическом хостинге не подключает API.

## Railway

Railway использует `npm run build` для сборки и `npm start` для запуска приложения на порту `PORT`. Node.js 24.12 или новее нужен встроенной SQLite.

Добавьте в Variables сервиса `TELEGRAM_BOT_TOKEN` и `COOKIE_SECURE=true`, затем включите публичный HTTPS-домен в Networking. Сервер возьмёт его из `RAILWAY_PUBLIC_DOMAIN`, зарегистрирует Telegram webhook и настроит кнопку меню. Если используете собственный домен, задайте `WEB_APP_URL=https://ваш-домен`. Один Railway-сервис обслуживает и приложение, и бота. Если база должна переживать перезапуски и новые деплои, подключите Railway Volume с путём `/app/storage`; приложение автоматически сохраняет базу в этот каталог. Либо укажите `DATABASE_PATH=/app/storage/blizhe.sqlite`. Настройте Railway healthcheck на `/api/health`.

Файл `.env.example` содержит шаблон локальных переменных. Не загружайте `.env` с реальным токеном в GitHub.

## Первый вход и работа пары

1. Создайте аккаунт с именем, email и паролем от 10 символов.
2. Сохраните секретный код восстановления. Отправка писем и подтверждение email пока не подключены; восстановление работает по этому коду. Код одноразовый, после восстановления выдаётся новый.
3. Откройте профиль через аватарку в верхнем углу. Загрузите фото, укажите день рождения, описание и дату начала отношений.
4. В разделе пары создайте приглашение и передайте код партнёру. Он регистрирует свой аккаунт и вводит код в настройках. Код действует 24 часа; в паре может быть два человека.
5. Даты, планы, фото и сообщения общие. Изменения второго участника появляются автоматически, примерно раз в 6 секунд при открытом приложении. При одновременном изменении приложение просит повторить действие, не перезаписывая свежие данные.

Каждый редактирует свой профиль. Отправитель сообщений определяется вошедшим аккаунтом. Для присоединения по приглашению личное пространство должно быть пустым: существующая история не переносится автоматически. Настройки также позволяют сменить пароль, выйти и скачать резервную копию истории.

## Данные

Аккаунты, хеши паролей, сессии, профили и общая история хранятся в storage/blizhe.sqlite на компьютере с сервером. SQLite использует WAL: для файлового резервирования сначала остановите приложение и скопируйте всю папку storage. Эта папка исключена из Git и закрыта для прямого скачивания через Vite. Фотографии сжимаются браузером перед сохранением. В интерфейсе нет автоматического переноса старых демонстрационных данных из localStorage; существующие данные браузера не удаляются.

Сессия хранится в HttpOnly-cookie на 30 дней. Пароли хешируются scrypt; одноразовые коды и токены сессий хранятся в хешированном виде. Есть проверка входящих данных, изоляция пространств и ограничение попыток входа. Для публикации в интернете необходим HTTPS и COOKIE_SECURE=true; HTTP по домашней сети предназначен для локальной проверки. Push-уведомления, письма и постоянный облачный хостинг не настроены.

## PWA

Установка на экран телефона доступна у готовой сборки через HTTPS. На iPhone: Safari → «Поделиться» → «На экран Домой». На Android: установка через меню браузера. Service worker кеширует только оболочку и статические ресурсы, не запросы API. Вход, загрузка личных данных и сохранение требуют соединения с сервером. В режиме разработки service worker не регистрируется.

## Telegram Mini App

Приложение можно открыть внутри Telegram. Скопируйте `.env.example` в `.env`, добавьте токен своего бота из @BotFather в `TELEGRAM_BOT_TOKEN` и оставьте `COOKIE_SECURE=true` для HTTPS. После изменения `.env` перезапустите сервер. Токен используется только сервером и не попадает в браузер.

1. Запустите приложение и откройте его по публичному HTTPS-адресу Railway либо через Cloudflare Tunnel.
2. В @BotFather откройте `/mybots` → выберите бота → **Bot Settings → Configure Mini App → Enable Mini App**. Укажите публичный HTTPS-адрес приложения.
3. После деплоя отправьте боту `/start`: он должен ответить кнопкой открытия приложения. Кнопка меню настраивается сервером автоматически. Если бот не отвечает, проверьте Deploy Logs: там будет видно, отсутствует ли токен/домен или Telegram отклонил webhook.

Первый вход в боте попросит войти или создать аккаунт; затем проверенные данные Telegram привяжутся к этой учётной записи. Последующие открытия Mini App будут входить в связанную учётную запись автоматически. Подпись Telegram и срок действия `initData` проверяет сервер. В Mini App работают оформление с учётом Telegram-темы, системные безопасные отступы и кнопка «Назад».

Cloudflare Quick Tunnel выдаёт временный адрес. Если адрес изменился, обновите URL Mini App в BotFather. Для постоянного адреса используйте именованный туннель или HTTPS-хостинг.

## Проверки

npm test проверяет календарные расчёты и API аккаунтов, приглашений, профилей и совместных данных. npm run build проверяет TypeScript и собирает фронтенд. Интерфейс вручную проверяется в браузере на мобильном и большом экране.
